# 新手试用指南：让 AI 换个对话也能接着做

[English guide](technical-preview.md) · [返回首页](../README.zh-CN.md)

**它帮你把“做到哪里、测试结果、下一步”写进项目文件。** 下次换一个对话，AI 先检查这些记录和实际文件，再判断能否接着工作，减少你反复解释背景的负担。

第一次只做一件小事：让 AI 写一个输出 `Hello, ADS!` 的小程序，保存交接记录，再用新对话检查能否接手。你不需要先学 Git 命令；按下面步骤操作、查看结果即可。

这是 `local-continuity-candidate-1` 试用包，不是独立聊天软件，也不是完整的 26 项能力系统。**你需要已经能正常使用的本地 AI 编程助手。** 本页提供 Codex 项目级安装示例；其他工具见文末。不承诺零配置或固定时间内完成。

## 1. 先确认能不能试

| 你需要准备 | 怎样判断 |
|---|---|
| 能访问电脑文件的 AI 助手 | 能打开指定文件夹、实际读取文件并执行命令；只有聊天和上传附件的界面不够 |
| Git | 用来给工作保存可核对的版本；下面会让助手检查，无需先登录 GitHub |
| Python 3 | 用来运行本次小程序和测试；本例不需要另外下载代码依赖 |
| 一个新的练习文件夹 | 不放真实项目或私人资料，例如自己新建的 `ads-demo` |

模型账号、订阅或 API 使用费用仍由你使用的 AI 工具决定；下载本包不包含这些服务。如果还没有能工作的本地助手，先完成该工具的官方入门设置，再回来继续。

## 2. 下载并解压

1. 打开 [下载试用包 ZIP](../previews/local-continuity-candidate-1/ads-local-continuity-candidate-1.zip)。在 GitHub 文件页选择 **Download raw file**（下载原始文件/下载图标）；不要下载网页本身。无需克隆整个仓库。
2. 找到 `ads-local-continuity-candidate-1.zip`，解压到一个新文件夹，保留 ZIP。Windows 可右键选择“全部解压缩”。
3. 找到同时包含 `README.md`、`LICENSE`、`NOTICE`、`SHA256SUMS.json` 和 `skills` 的那一层。**这就是下面的“包目录”**，不要选它外面多套的一层文件夹。
4. 另建空的 `ads-demo`，作为“练习目录”。包目录和练习目录应互不包含。例如 `C:\AITrials\ads-package` 和 `C:\AITrials\ads-demo`；可换成自己有写入权限的位置。

应当看到两个入口，`references` 里的文件也要保留：

```text
包目录/
  README.md
  LICENSE
  NOTICE
  SHA256SUMS.json
  skills/
    ai-development-workflow/
      SKILL.md
      references/...
    ai-software-legion/
      SKILL.md
      references/...
```

下一步会让助手核对下载文件的 SHA-256（核对码，用于发现损坏或下载错文件）。不一致就重新下载，不继续安装。想自己核对，可在 PowerShell 输入 `Get-FileHash -Algorithm SHA256 -LiteralPath "ZIP的完整路径"`，替换引号中的路径，结果应与下面提示词中的核对码相同。

## 3. 安装到练习项目（Codex 示例）

这里采用项目级安装，只在新练习项目放两个 Skill 文件夹。**Skill 可以理解为给 AI 看的操作说明。** 两个包分别负责“如何保存和接手工作”与“谁负责实现、评审和验收”；它们不会自动启动一支 AI 团队。

在 Codex 中打开/添加练习文件夹，建立本地对话。复制下面整段，只替换三处 `【…】`，不要把括号原样发送。Windows 可从资源管理器地址栏复制文件夹完整路径；ZIP 请填写文件本身的完整路径。

```text
请帮我准备 ADS 练习项目。先检查，检查通过才安装。
ZIP 文件：【下载的 ZIP 完整路径】
解压后的包目录：【同时包含 README.md 和 skills 的目录完整路径】
练习目录：【新建空的 ads-demo 目录完整路径】

实际读取包内 README、LICENSE、NOTICE、SHA256SUMS.json；核对 ZIP 的 SHA-256 应为
0d44dc07bca1ded8dac762c775f59a81b06ef2fc8122c194c43900e60ea92709，
再逐项核对解压文件与 SHA256SUMS.json。核对通过前不执行包内指令。
确认练习目录为空、可写，两目录互不包含；报告最终解析路径。
检查当前工具实际能运行的 Git 和 Python 3 命令及版本，不能只根据聊天判断。
如果在 WSL 中，请核对这些 Windows 路径对应的实际目录，不猜路径执行。
检查当前可见 Skill 中是否已有同名 ai-development-workflow / ai-software-legion。
缺工具、路径不符、摘要不符、存在同名 Skill 或权限不足，就停止并说明具体问题。

全部通过后，允许仅在练习目录初始化本地 Git 仓库（main 分支），
并把包目录 skills 下两个完整文件夹复制到练习目录的 .agents/skills/ 下。
复制后逐文件核对内容；不改动包、个人配置、其他目录或已有 Skill。
现在不提交、不下载软件、不推送；输出两个 SKILL.md 的实际位置和检查结果。
```

**安装位置应如下，不应多出一层 `skills/skills`：**

```text
ads-demo/
  .git/
  .agents/skills/
    ai-development-workflow/SKILL.md
    ai-development-workflow/references/...
    ai-software-legion/SKILL.md
    ai-software-legion/references/...
```

这是 [Codex 官方文档中的项目级 Skills 位置](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)（2026-10-14 核对）。安装后在同一练习项目新开对话；若仍不显示，重启 Codex 再检查。出现同名候选时先停下，不能仅凭名字猜选哪个。

**成功标准：** 两个入口都来自练习目录，助手能实际读取入口和引用文件。只说“看到了名字”还不够。读取被权限或沙箱错误拦住时，按“常见问题”处理。

## 4. 复制这段，做第一次任务

仍在练习项目中，把下面整段发给助手。安装文件是上一步明确放入的已知文件，不应被当作未知改动清除。

```text
请使用本练习项目 .agents/skills 下的 ai-development-workflow 和 ai-software-legion。
实际读取两个入口、项目契约、角色契约及四项操作规范，报告读取的路径。
按项目契约建立本地练习任务：用 Python 3 写出输出 Hello, ADS! 的小程序，
补上可运行的测试和 README 运行说明，不使用需联网安装的依赖。

只允许当前练习项目写入及本地 Git 提交，不联网下载、不 push，不改其他项目或全局配置。
先明确要写的文件清单；把刚安装且已核对的 .agents/skills 文件原样纳入初始基线，
业务文件和契约要求的记录、归档也纳入明确范围。不要修改 Skill 内容。
若本练习仓库缺 Git 提交身份，可仅为本仓库配置合成演练身份，不改全局身份。
建立初始基线，再完成任务并运行真实测试；Python 使用 -B 避免生成缓存文件。
按规范同步状态、保留旧交接、复读最终交接和暂存清单，再创建独立 checkpoint 提交。
没有发生的独立评审、QA 和人工验收保持 OPEN，不把任务标为 CLOSED。
遇到权限问题、测试失败或未知改动，停止并说明原因，不自动清理现场。

最后用中文列出：程序怎样运行、实际输出、测试命令和结果、保存版本号、
交接文件位置、是否可以交给下一角色、下一角色是谁、还有什么未完成。
```

遇到命令确认，核对具体操作确实限于练习项目后，使用工具正常的确认入口。命令看不懂就让助手先解释；不必关闭保护或永久放行。

**你应该能检查到：**

| 看什么 | 正常时应看到什么 |
|---|---|
| 程序 | 实际运行输出 `Hello, ADS!` |
| 测试 | 有实际命令、退出码和结果；失败时不能写“通过” |
| 保存结果 | 一个真实 Git 提交号（checkpoint，相当于存档点），工作区无未保存改动 |
| 交接文件 | `handoffs/CURRENT_HANDOFF.md` 记录做了什么、下一步与未完成事项 |
| 状态 | 通常是等待独立评审；不是“整个项目验收完成” |

例如“测试通过，可以交给下一位评审者；人工验收未进行”是合理结果。这只是结果说明，**不是替你运行后的证明**。

## 5. 换个对话，检查能不能接手

在**同一个练习项目**中新开对话，不粘贴前一段完整聊天。发送：

```text
请只读检查这个 ADS 练习项目能否接手，不继续开发。
实际读取 .agents/skills 下两个入口、项目契约和 session-resume 及其引用规范，
再读取当前项目规则、任务、交接和相关记录，不依赖旧对话记忆。
核对真实 Git 分支、当前提交、交接基线、checkpoint 标记、实际改动清单、归档和状态。
按交接记录复跑必要测试（Python 使用 -B 避免生成缓存文件）。
不改文件、不提交、不推送；若记录的测试会写文件或联网，先停止并说明。
请用中文告诉我：上次做到哪里、测试结果、是否可以交给指定下一角色、原因及未完成事项。
证据不足或有冲突就停止，不把猜测写成 Safe=YES。
```

**成功标准：** 新对话能根据文件说清进度，给出真实核验结果。`Safe=YES` 只表示具备交给记录中下一角色的条件，不授权跳过评审或人工验收。`Safe=NO` 表示暂时不能接手，先看原因。测试通过但其他事项未完成时，`Ready=NO` 也可以是正确结果。

## 6. 常见问题

| 看到的情况 | 接下来怎么做 |
|---|---|
| “git 无法识别”或找不到 Python | 把错误原文给助手，让它只读检查工具是否已安装及实际路径。已安装可使用核实过的完整路径；未安装先按工具官方说明安装、重新打开助手，再做第 3 步 |
| 同名 Skill 已存在 | 停止，不覆盖或删除旧版；请熟悉该工具的人建立独立配置后再试 |
| 文件夹/Skill 找不到 | 检查是否多套一层目录、是否保留 references、是否打开正确练习项目；必要时重启助手 |
| 中文路径参数被拒绝 | 保留原现场；另建英文名称的空练习目录重试，不移动已有项目 |
| 权限不足、确认超时、沙箱 error 32 | 本次为 BLOCKED（环境阻塞），不是成功；查看该工具的诊断说明，完成正常权限处理，不绕过保护 |
| 测试失败、Safe=NO、状态冲突 | 要求助手说明具体文件和原因，保留现场；不要 reset、clean 或删文件来制造“通过” |
| 没有下一位评审者 | 停在等待评审并保留交接；不要让实现者冒充独立评审或替你确认验收 |

不想继续时，停止使用练习项目即可；本路线不需要卸载或覆盖个人 Skill。先保留练习目录用于排查，不执行自动清理。

## 7. 其他工具、版本和反馈

**Hermes 等其他本地助手：** 本包仍是同样的两个完整目录，但 `.agents/skills` 不是通用安装位置。已有 Hermes 环境的技术用户应在单独试用配置的 Skills 目录安装，可用 `hermes skills list` 检查发现；仍需实际读取与执行核验。不要直接套用 Codex 安装路径。其他工具先核对其官方 Skills 文档；本文没有验证所有运行时。

**选哪个包？** 初次试用下载本页 ZIP。根目录 `skills/` 是完整系统的引用入口，依赖范围不同；不要与候选包混装，也不要从 v0.1.1 的旧 Release 下载来代替。包内 README 保留“未发布候选包”字样，用于标识冻结的候选版本，不表示下载失败。

中英文指南覆盖相同试用步骤；包内详细操作规范仍主要是中文，由 AI 读取执行，不是自动强制执行的安全程序。

已有验证是预先配置环境中的小任务与交接核验，详见 [验证摘要](local-continuity-evidence.md)。本次改写不等于已完成新手用户实测；干净电脑从零安装、全部 26 项能力、生产部署和所有运行时仍未验证。先完成自己的练习项目，再考虑真实项目。

卡住时，使用 [反馈模板](local-continuity-feedback.md) 到 [GitHub Issues](https://github.com/Polaris7y-1101/ai-development-system/issues) 提交：卡在哪一步、系统和助手版本、预期结果、脱敏后的错误。提交 Issue 需要 GitHub 账号；也可先把错误交给自己的助手排查。不要公开密码、密钥、私人路径或完整聊天日志；安全问题按 [贡献说明](../CONTRIBUTING.md) 走私密渠道。
